## Follow-up on the two survivors

* **M20 (replayer delivery not re-sorted)** was a real test gap: `ReplayPlanTest` checked each fault's
  delay value but never that the record actually moved in the sequence. Added
  `ReplayPlanTest.delayedRecordsAreReallyDeliveredLater`; re-running only M20 now **caught**
  (`results/hand-mutations-rerun.md`).
* **M14 (capacity-fade releases due cycles newest-first)** is still not caught, and it turns out to be
  an equivalent mutant: `CapacityFade` registers one event-time timer per summary timestamp, and Flink
  fires event-time timers in timestamp order, so each `onTimer` call only ever finds one due
  timestamp and the sort over `due` never has more than one element to order. The new
  `CapacityFadeOrderTest` (scrambled arrival, one watermark passing six cycles) passes with and without
  the mutation, which is what confirmed this. The test is kept because it pins the behaviour that
  matters (event-time order despite scrambled arrival); the sort is kept as cheap defence.

Net: 19 of 20 caught after the follow-up; the remaining one is equivalent.
